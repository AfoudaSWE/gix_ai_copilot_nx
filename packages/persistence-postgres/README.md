# @gixcopilot/persistence-postgres

> **Status:** Beta. See [stability levels](https://github.com/AfoudaSWE/gix_ai_copilot_nx/blob/main/docs/VERSIONING.md#stability-levels).

Production PostgreSQL persistence for the AI Copilot SDK (**Beta**): tenant-scoped
conversations (threads, messages, runs), durable memory, append-only audit, usage events,
and the reviewed migration runner. Server-only; requires PostgreSQL 16+ with the `vector`
extension for knowledge and semantic memory.

## Install

```bash
npm install @gixcopilot/persistence-postgres
```

Requires Node.js >=22.12.0. ESM only.

```ts
import { createPostgresPersistence } from '@gixcopilot/persistence-postgres';
import { createConversationRecorder } from '@gixcopilot/tenancy';

const persistence = createPostgresPersistence({ connectionString: config.secrets.databaseUrl?.reveal() });
// Deploy step (not app startup): `aicopilot db migrate`, or `await persistence.migrator.up()`.
const server = createServer({
  ...,
  requireAuthentication: true,
  runObservers: [createConversationRecorder(persistence.conversations)],
});
const audit = persistence.audit;                       // AuditSink for the Action Firewall
const memory = persistence.memory();                   // MemoryStore for createMemoryService
const ready = await persistence.health({ checkMigrations: true });
```

**Tenant isolation.** Data is reachable only through `forTenant(scope)` handles
(`conversations.forTenant`, `audit.forTenant`); every statement filters by `tenant_id`, with
project and environment narrowing when present. Memory queries filter by owner *and* tenant
and check `assertMemoryAccess`. There is no unscoped query API to forget a filter on. Tested
against real PostgreSQL with two tenants across threads, memory, knowledge, workflows and
audit (`postgres.integration.spec.ts`).

**Audit** is append-only in the database itself: a trigger rejects `UPDATE` and any
`DELETE` except `purgeBefore()`, the documented retention purge.

**Migrations** (`createMigrator`): SQL generated by drizzle-kit from `src/schema.ts`, then
reviewed and committed, with hand-written additions (foreign keys, triggers). Applied in order
(workflow checkpoints, pgvector, platform) under an advisory lock, one transaction per
migration, recorded with checksums (an edited applied migration stops the run). Rollback runs
only a reviewed `.down.sql` and refuses otherwise. See
[docs/production/DATABASE.md](../../docs/production/DATABASE.md) for expand/migrate/contract.
