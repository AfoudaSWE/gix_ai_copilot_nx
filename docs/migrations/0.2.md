# Migrating from 0.1.x to 0.2.x

**Breaking API changes: none.** 0.2.0 is the first release that publishes all 42
`@gixcopilot/*` packages together at one version. The 0.1.0 and 0.1.1 releases were partial
(some packages missing or behind) and are deprecated; see
[Releasing](../RELEASING.md#what-happened-with-010-and-011).

## Upgrade

Set every `@gixcopilot/*` dependency to the same version and reinstall:

```json
"@gixcopilot/node": "^0.2.2",
"@gixcopilot/react": "^0.2.2"
```

Before 1.0, a caret range does not cross a minor version (`^0.1.1` never resolves to 0.2.x),
so the range has to be edited by hand. Keep all `@gixcopilot/*` packages on one version.

## Behavior change: a timed-out tool is now stopped

Before 0.2.0, when a tool call exceeded its timeout the run recorded a `TIMEOUT` error, but the
tool kept running: the `signal` it received never fired, so it could still cause side effects.
Now each tool call gets its own `signal`, which aborts when the run is cancelled **or** when
that call's timeout elapses.

- Tools that honor `signal` (pass it to `fetch`, check `signal.aborted`) now stop at the
  timeout. This is the intended behavior; no change is needed.
- Tools that ignore `signal` behave as before.
- In `@gixcopilot/testing`, a mocked tool that times out now reports its call outcome as
  `cancelled` instead of `pending`. Update assertions that expected `pending`.

## Generated projects

Projects created with `aicopilot init` or `npm create @gixcopilot` before 0.2.1 pinned
`vitest` to an exact version that makes npm 10 crash during `npm install`
(`Cannot read properties of null (reading 'edgesOut')`). Either regenerate the project, or in
its `package.json`:

- node, react and enterprise templates: change `"vitest": "5.0.1"` to `"vitest": "^5.0.1"`, and
  for yarn 1 add `"vite": "8.3.0"` to `devDependencies`.
- angular template: add `"overrides": { "vitest": "4.1.11" }`.

## Database

No schema changes between 0.1.x and 0.2.x.
